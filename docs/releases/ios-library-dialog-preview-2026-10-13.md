# iOS Jellyfin / Emby 媒体库弹窗预览

日期：2026-10-13。对照用户提供的双端截图与当前共享 `EmbyBrowser.tsx`、`MoviePushPanel.tsx`，在指定客户端仓库更新 RN 界面；无 EAS、无 IPA、无发布，版本保持 1.7.5 / build 17。Expo Go 可检查界面，现有旧 IPA 不含本次修改。

## 界面与操作

- 添加面板保留来源、已保存挂载、浏览入口、播放方式及简短提示；媒体账号与挂载管理保持折叠，搜索与选集移到独立弹窗。
- 浏览弹窗支持展开/还原、媒体库搜索、逐级目录/返回、列表/海报墙图标切换、多选和全选；底部选择计数、取消和添加操作保持可见。
- 点击目录继续浏览，点击文件高亮选择；单选点击「添加当前条目」，多选点击「添加 (数量)」。成功更新片单并清除成功项，失败项保留；整部/整季仍经过确认，保存一张可切集的片单卡。
- 整部/整季按钮仅在直属下一层非空、全部是可播放影片时启用。含子目录、空目录、图片/音频等非影片或检查尚未完成时禁用；后台检查最多四个并发请求，取消旧目录检查。提交时重新检查直属下一层，不递归穿过子目录添加，防止目录变化后绕过限制。
- 电影/文件夹用 2:3 海报，Episode 用 16:9 缩略图；与双端一致采用 cover 裁切，保持比例而不拉伸。长名称完整换行，目录可显示子项数量。
- 默认服务器转发，直链直连使用服务端返回的 `directUrl`；没有该字段则回退转发并同步 `directLink:false`。不增加浏览器转码开关，原生 VLC 负责播放。

## 验证

107 项 JS 测试、类型检查、lint 通过。新增业务回归覆盖 Emby/Jellyfin 的默认转发、明确直连以及直链缺失时的回退与条目身份保留，并检查整部添加对空目录、混合目录、非影片的拒绝及纯影片目录的合法添加。共享 Go 与原生桥本轮未修改。

浏览器预览使用本机独立服务、七个几何测试海报条目，不访问或修改 NAS：

| 视口 | 海报墙列数 | 检查 |
| --- | --- | --- |
| 手机竖屏 390×844 | 2 | 卡片无横向越界，海报 2:3，固定底部按钮可见 |
| 手机横屏 844×390 | 3 | 同上，弹窗内容可滚动 |
| 平板竖屏 768×1024 | 3 | 同上 |
| 平板横屏 1366×1024 | 4 | 同上 |

Jellyfin 通过单片、逐级目录、双集多选及整季卡添加；Emby 通过相同弹窗入口与搜索/单片添加。列表模式每行占满内容宽度，Episode 海报实测 16:9。图片请求继续由 `SourcePoster` 使用选定服务器的认证通道，不把媒体库认证凭据交给 Image URL。截图与测量数据保存在被忽略的本机 `.ui-validation/ios-20261013`，只用于界面证据。

本轮是源码和浏览器界面验收；iOS 原生 Modal、真实媒体库图片与直链网络、Range/HLS/seek 及 VLC 解码待用户设备验证。未构建新的安装包。
