# iOS 1.8.5 / build 23 播放回归修复验证

日期：2026-10-13。用户要求修复加载/起播卡死，同时保留 B站声音和一起听桌面/锁屏播放，再构建 IPA 供真机复验。仅本地提交，不发布 GitHub。

## 修复及构建差异

build 21 的共用 VLC 路径存在底层锁与主线程同步通知相互等待的风险，符合 Jellyfin、B站和一起听的卡死反馈；未取得设备线程栈。所用 VLCKit 4.0.0-a24 默认同步事件配置，播放器创建前改用该版本的主队列异步事件配置 `VLCEventsLegacyConfiguration`。系统进度/中断/路由 observer 使用 queue:nil，再 main.async 处理；销毁前解除 delegate。保留 B站分离音轨延迟挂载/成功去重/重试，以及音乐专用后台标记、no-video、关闭隐藏 PiP、激活 playback 会话和避免空闲语音引擎争抢会话。详细来源与等待链见 [build 22 记录](ios-1.8.5-22-validation.md)。

build 22 已通过 Xcode 编译，但打包前 `strings` 主程序符号检查误报并退出，没有 IPA。Apple cctools 的 strings 默认扫描 Mach-O 段，导入类名可位于段外链接数据。build 23 仅修正产物验证方法：读取整个主程序和 VLCKit framework 的二进制，要求主程序包含事件配置类及 setter 引用、框架包含对应类定义。并未放宽为只查框架，未修改 build 22 的播放修复。
