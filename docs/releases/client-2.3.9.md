# ZViewer-Client V2.3.9

Android / HarmonyOS 更新为 **2.3.9（versionCode 239）**，包含未单独公开发行的 2.3.8 适配及本次 P1 完善，对齐服务端 v5.2.1 / Piik v24。

## 🚀 新特性 / Features

- 双端屏幕共享与房间语音迁移至 Piik v24，复用房间信令连接，支持观众协助转发、换父及共享/语音独立启停。
- 支持自定义整数 FPS 和共享中、暂停中调整画质；Android 最高取屏幕刷新率与 90 fps 的较小值，HarmonyOS 最高 60 fps，实际表现以采集与编码实测为准。
- 接入编码健康自动降档：连续两个有效采样窗口确认编码不足后降一档，每次采集最多一次，结果与原因可见。
- 房主与观众提供逐连接诊断，展示连接方向、状态、画面尺寸、编码格式、区间帧率/码率、RTT、丢包、编码耗时及参数回读。

## 🐛 错误修复 / Bug Fixes

- 修复观众在宽限期内信令重连时，客户端清空仍有效媒体连接、画面不再恢复的问题；缺失或失效边主动请求重新选路。
- 修复暂停中 sender.track 为空时无法更新视频参数的问题；新连接应答后应用当前画质。
- 参数拒绝或关键回读不一致时恢复原配置，恢复失败则结束捕获；观众同时离开不会导致整场画质更新失败。
- 隔离暂停、换流、重连和手动调整的健康观察基线，静止画面、证据不足与仅带宽拥塞不误降档。
- 修复旧统计跨会话回写、没有远端 RTCP 时伪报零丢包，以及接收兼转发时重复汇总码率的问题。
- HTTP、严格 HTTPS 和显式证书例外共用原生 Cookie 通道，支持 Piik 站点票据、IPv6 与反代前缀，严格证书校验继续生效。

## ⚠️ 破坏性改动 / Breaking Changes

- **屏幕共享与语音只支持 Piik v24。旧服务端、旧 SFU/LiveKit 合同不再兼容，需使用支持该合同的新服务端。**
- 移除 LiveKit 客户端依赖和旧组件下载流程；Piik 服务端尚无房主全局禁言/移出合同，因此隐藏这些管理入口，本机成员音量仍可调节。
- 本次仅发布 Android / HarmonyOS；iOS / iPadOS 保持 2.3.6 / build 40，未迁移 Piik，也未构建 IPA。
- 最低系统与发布签名沿用：Android 7.0 / API 24，HarmonyOS 6.1 / API 23。

## ⚡ 性能优化 / Performance Improvements

- 不设置固定视频码率上限，由 WebRTC 拥塞控制分配带宽；画质调节复用现有捕获与视频轨，不重复申请录屏授权。
- 逐边采样基线独立，统计请求四秒超时且轮询不重叠；自动降档失败不无限重试。
- 媒体协商等待 20 秒、持续断连等待 12 秒后交给服务端重新选路；同会话媒体失败累计三次后提示手动重连，信令恢复保留三十次上限。
