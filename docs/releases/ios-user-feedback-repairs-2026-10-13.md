# iOS 1.8.0 / build 18 用户反馈后的源码修复

日期：2026-10-13。版本号及 buildNumber 保持 1.8.0 / 18。**本轮没有启动 EAS、构建 IPA、推送或发布；已有 build 18 安装包不包含本轮修改。**

## 修改范围

| 用户问题 | 源码处理 |
| --- | --- |
| 弹幕缺少显示区域 | 增加 25%–100%、5% 步进的设置，保存本机偏好；滚动与底部固定弹幕共同限制在该画布中，旧偏好保留 70% 默认值。 |
| 服务端选择 B站视频后 iOS 报其他设备本机地址 | 房间影片 DTO 决定实际来源、当前 P 和 CID；即使广播漏填或误填来源，也从该影片恢复规范链接，丢弃其他设备的音轨地址，由本机重新解析。 |
| iOS 有画面无声音 | VLC 的 `addPlaybackSlave` 从空输入初始化阶段移到输入开始播放时；失败不记为已添加，后续进度回调可再试，成功按 URL/类型去重。音轨继续由同一 VLC 输入同步，不启动第二套音频播放器。 |
| iOS 添加 B站影片后网页观众黑屏 | 本机播放保留页面身份；普通视频独立通过服务器解析媒体，向房间广播无本站 token 的服务器代理视频/音频地址。播放、暂停、拖动保留最新时钟，不被解析时的旧状态覆盖。PGC 保留各设备 CLI 的合同。服务器解析失败显示观众地址准备失败，本机播放不等待服务器账号；重试播放可重试该解析。 |
| B站诊断报网页内容 | 先使用实际播放解析器，再探测本机媒体能力地址或服务端媒体代理；不对 B站页面执行媒体 HEAD。其他设备的 loopback 地址仍不能当普通影片使用。 |
| 一起听搜索和我的栏目 | 主音乐来源页及关联视频均提供独立弹窗，支持展开；搜索海报维持原比例。卡片宽度向下取整，避免 onLayout 像素舍入使最后一列换行。关联视频选定后直接保存该 P/CID。 |
| 评论/队列退出全屏 | 弹窗挂在全屏 Modal 内，关闭后仍为同一播放器；打开弹窗不关闭全屏、不释放背景视频。 |
| 拖到曲尾无法继续 | 区分待执行 seek、正在 seek、原生停止及自然结束；忽略旧进度和 seek 暂停，seek 后恢复当前播放意图，显式暂停优先。音乐拖动上限保留末尾 0.25 秒，临时暂停不广播成全房暂停，自然停止才进入续播判断。 |
| 歌单没有返回 | 在“搜索音乐”左侧增加返回上一级，返回原音乐来源页，退出该歌单批量操作并清理歌单展示状态。 |
| 播放顺序不明确 | 按用户最后指定的四种参考图标实现透明矢量形状：列表顺序、循环带 1、随机、循环。点击直接按“顺序循环 → 按顺序播放 → 单曲循环 → 随机播放”循环；不弹模式选择框，观众不能修改房间模式。使用已安装 expo-image，无新依赖。 |
| 退到桌面无声 | 已加入的一起听在 Socket connecting/joining/waiting 时保持组件和 VLC 实例，避免断线触发卸载；离房、错误、被踢、关房仍释放。媒体 loading 状态也登记系统媒体 URI。房主重连时同一已加载曲目采用本机进度和播放状态再同步，观众按权威状态对齐。 |

## 验证

- 完整 JS 测试 **166/166 通过**，包括真实 MusicPanel 控制/心跳回调、曲尾 seek、显式暂停、FM 单曲循环、旧曲目回调隔离、B站跨端状态及本机媒体探测。
- 完整 iOS `npm run typecheck`、`npm run lint` 通过；本轮未生成或修改 `ios/`。
- 在安装的 expo-libvlc-player 57.0.54 Swift 源码副本上执行原生插件，确认初始化不添加 slave，播放时添加、返回成功才去重，并确认重复执行内容不变。**此项不是 Swift 编译或设备听音验收。**
- 本机可丢弃 HTTP/Socket 测试数据，经实际 Expo/RN Web 页面验证：四模式逐次切换且没有模式弹窗；歌曲评论与队列关闭后保留全屏；歌单返回原来源页；搜索及个人栏目独立弹窗；停止测试服务、断线重连期间全屏页保持。
- 六张搜索卡片在 390×844、844×390、768×1024、1366×1024 中分别为 **1/3/2/3 列**，均无横向溢出。封面使用几何测试图，未用实际账号和在线歌曲。
- Expo Go 服务已启动供界面预览。Web/Expo Go 没有 VLC 原生内核，页面的原生模块缺失提示是预览边界。

本机截图、测试日志、响应式 JSON 和 fixture 保存在被 Git 忽略的 `.ui-validation/ios-user-repairs-20261013/`；不进入发布源码。
