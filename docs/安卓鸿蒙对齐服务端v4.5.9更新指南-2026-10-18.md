## 3. 一起看：先统一协议，再替换进度校正

### 3.1 已核实的协议变化

| 事件/字段 | 新服务端合同 | 客户端迁移要求 |
| --- | --- | --- |
| `watch-together-state`、`watch-together-control`、`host-heartbeat` | 上行允许附带 `clientTs`，单位 Unix 毫秒 | 在发送时采样，不能复用旧缓存时间；缺省时服务端不做传输延迟补偿 |
| 写侧延迟补偿 | 播放中补 `clamp((now-clientTs)/1000, 0, 1.5) × playbackRate`；暂停不补 | 不在客户端重复补同一段延迟；这不是完整跨设备时钟校准 |
| `sync-heartbeat`，`source='server'` | 一起看活动房间每 2 秒广播权威推算状态，房主在线时也发送；含可选 `hostOnline` | 作为常规进度校正路径；不同时绑定旧 `server-heartbeat` 重复处理 |
| `watch-together-check-status` | 上行 `{roomId,currentTime,isPlaying,playbackRate,clientTs}`；ack 为 `{success,data:{needsSync,state?,serverTs?}}` | 每 10 秒自检，复用心跳纠偏函数；仅 `needsSync=true` 且有 `state` 才应用 |
| 自检容差 | 播放/暂停不一致，或进度偏差超过 10 秒，触发纠偏 | 10 秒是兜底容差，不能拿它替换常规软同步/硬 seek 阈值 |
| 初始状态 ack / 心跳的 `hostOnline` | 用于校正房主在线状态，覆盖错过离线事件的观众 | `false` 进入自主控制；`true` 恢复跟随；字段缺省不当作 `false` |
| 无 `diff` 的全量 state | 上游以此识别 `forceSync`，包括“同步进度”操作 | 保留显式强制进度应用，不能将所有 state 广播都降为只换源 |

### 3.2 实施入口

客户端重点修改 `src/upstream/modules/sync-playback/` 下的 `types.ts`、`constants.ts`、`hooks/useHostBroadcast.ts`、`useHostHeartbeat.ts`、`useViewerStateSync.ts`、`useViewerSync.ts`，以及 `src/upstream/modules/playback-memory/` 的类型、导出、`useServerHeartbeat.ts` 和 `usePlaybackStateRequest.ts`。同步检查 `src/upstream/modules/room/watch-together/WatchTogetherCore.tsx` 等组合调用者。

上游参考为同名 `frontend/src/modules/` 文件，后端合同位于 `backend/src/modules/playback-memory/`、`backend/src/modules/sync-playback/heartbeat.handler.ts` 和 `backend/src/modules/shared/dto/sync-state.dto.ts`。

实施顺序：

1. 补齐可选 DTO 字段、事件名及 ack 类型，再给房主的普通广播、强制广播、控制和存活心跳附加 `clientTs`。
2. 将软同步/硬 seek 校正收敛到服务器心跳路径。复用现有 `executeSeek`、`seekTo`、`reloadVideo` 和 suppress 保护；不要把 MSE seek 全部改成直接写 `video.currentTime`。
3. 收到 `hostOnline` 时先更新自主控制状态，再判断是否跳过心跳。否则房主离线后才入房的观众可能每 2 秒被强制恢复播放。
4. 保留换源、播放/暂停、倍速和显式 seek 控制；普通 state 不再与服务器心跳争夺进度。无 `diff` 的强制同步仍需硬校正，覆盖进度为 0 的场景，不直接照搬上游只判断 `currentTime > 0` 的分支。
5. 自检设置在途锁、ack 超时释放及房间/媒体代次校验。上游当前 hook 的在途锁主要依赖 ack 回调释放，移植时应补丢 ack 和切房后迟到 ack 防护。
6. 离房、切服、换片、角色变化时清理定时器、软同步倍速和延迟重连 seek；不要让旧房间请求影响新影片。

旧服务端兼容需明确选择：建议继续支持 v4.5.3，在当前连接确认收到新服务端权威心跳后切换模式；换服清空能力状态。没有新心跳/自检 ack 时走有界旧路径，不允许新旧路径同时改进度。若决定提高最低服务端版本，应在连接页明确提示并更新版本要求，而不是让旧服静默失去同步。

## 4. 一起听：接入服务器基线，保留现有移动端修复

新后端新增 `MusicPlaybackState` 实体、`music-playback-memory.service.ts`、`music-broadcaster.service.ts`，`MusicSyncHandler.ts` 接收房主上行并持久化、外推播放状态。路由业务迁入 `backend/src/modules/music/`；路由文件搬迁不等于所有 URL 改名，应以 `backend/src/routes/register.ts` 实际装配为准。

| 合同 | 对齐方式 |
| --- | --- |
| 房主 `music:sync-state` / `music:host-heartbeat` | 保留完整曲目状态并新增 `clientTs`；房主心跳每 2 秒发送，回到前台补发 |
| `music:sync-heartbeat` | `{roomId,source:'server',state,hostOnline?}`；`state.positionSec` 已由服务端外推，直接消费，不能再用本地 `updatedAt` 做二次时间补偿 |
| `music:check-status` | `{roomId,positionSec,isPlaying,clientTs}`；ack 的 `data` 为 `{needsSync,serverTs,state?}`；每 10 秒，10 秒兜底容差 |
| `music:get-state` | 初始 ack 在 `queue`、`syncState` 外增加 `serverTs`、`hostOnline`，仍保留当前入房确认与退避重试 |
| 主路径与兼容 | 新服务器心跳同曲对齐阈值为 2 秒；上游 7 秒未收到服务器心跳才回退消费房主心跳，不能把这个阈值当作房主离线判据 |
| 曲目身份 | `trackKey` 区分 `ncm:<songId>` 与 `bili:<bvid>:<cid>`；不能只靠 `trackSongId` 区分 B站曲目 |

入口是客户端 `src/upstream/modules/music/hooks/useListenTogether.ts`、`types.ts`、`constants.ts`、`store.ts`。参考上游新增 `utils/serverSync.ts`、`hooks/useAudioEngine.ts`、`hooks/useQueueAdvance.ts`、`audioElement.ts` 和 `biliAudioCache.ts`，先迁协议再拆文件。

必须保留客户端既有行为：`widget/player` 队列归属、防重复弹窗、全屏工具栏循环修复、50% 初始音量及已保存静音值优先、私人漫游等待入队 ack、离房取消旧请求、触屏搜索、系统媒体 session 归属与后台音频路由。不能覆盖 `useListenTogether.ts` 后让这些已修复行为消失。

自检避开未就绪音频、seek、本地 B站试听、自主控制以及切曲过程；ack 返回时再次校验当前房间和曲目。新服务端重启后的队列与播放记忆恢复、房主先离线再加入、NCM/B站跨来源换曲需单独验证。

## 5. 媒体路由：贯通 DTO、添加入口与所有播放引擎

### 5.1 新字段不能只加在类型里

| 字段 | 服务端含义 | 客户端落点 |
| --- | --- | --- |
| `directLinkProxy?: boolean` | `directLink=true` 时：默认 false 为强制直连；true 为始终服务器中转，不先试直连 | `roomStore.ts` 的 Movie/DTO、转换、add/update 参数；MP4/挂载表单及 resolver |
| `serverProxy?: boolean` | ani/Kazumi/CMS 数据源的服务器中转开关；默认 false，不自动防盗链代理兜底 | 数据源添加、片单恢复、重新解析和 HLS/playsvideo 路由 |
| `sourceMountId?: number|null` | 精确锚定挂载；旧数据 null 时服务端按 `serverUrl + source` 回退匹配 | 挂载选择、添加/编辑影片及 DTO 映射；同地址多账号不混淆 |
| `source='cms'` / CMS `sourceMeta` | 标识站点、影片、播放组和集数，以便播放时重新解析 | 联合类型、映射、添加与播放分支；不能误解包成 ani 的 `episode` |

当前客户端 resolver 位于 `src/upstream/modules/room/watch-together/movie-source-resolver.ts`、`resolveSource.ts`；上游已搬至 `frontend/src/modules/movie-source/resolver.ts`、`resolveSource.ts`。先建立映射再移植，不能因旧路径在上游消失就直接删客户端文件。

### 5.2 路由必须一致

- 中转关闭：MP4、HLS 主/子清单、分片、密钥、init map、playsvideo Range 请求都遵守源站直连；失败给可操作提示，不悄悄耗用服务端媒体带宽。
- 中转开启：首个媒体请求即走服务器；无 Referer/UA 也必须代理。不能沿用“只在 headers 存在时包装代理 URL”的旧 helper 行为。
- Android/鸿蒙到已选服务器的本机连接通道仍属于传输层；它与“是否由服务端转发源站媒体”是两件事，不能因本机 URL 是回环地址就改写产品路由策略。
- 保留 `getApiUrl()`、`apiFetch`、`connectionTransport` 的逻辑地址转换和证书例外。上游 HLS loader 的 `logicalUrl/transportUrl` 是恒等函数，不能覆盖客户端的原生通道实现。
- 保留已有 `library-hls-proxy.ts`：相对片单、分片、AES key 仍以源站清单为基准；token 留在服务端代理请求，不传播给第三方 CDN。
- `noProxyFallback` 需从 Movie 经过 resolver、PlayerSource 传到 direct、HLS、playsvideo，各引擎遵守同一决定；`cliOnly` 的本机 B站解析约束独立保留。
- 普通网页的 HTTPS→HTTP 混合内容检查不能直接当作 ArkWeb/Capacitor 结论；按实际本机加载来源、连接通道和原生策略测试，避免仅根据 `window.location.protocol` 拦错。

### 5.3 FTP 与挂载特别注意

新 `/api/stream/resolve-ftp` 返回 `/api/stream/proxy-ftp?ticket=...`，旧 `proxy-ftp` 的用户名/密码 query 形式已移除。票据绑定签发用户，闲置 30 分钟失效，活跃使用滑动续期。

当前客户端已经调用 `resolve-ftp`，不应误报为“完全不支持票据”；真正要核验的是相对 URL 转换、过期重新解析，以及房间其他用户不能复用房主专属票据。保存逻辑挂载/影片身份，由各端按自身鉴权重新获取可播放地址；不要把临时 ticket 或设备回环地址当成永久片单身份。

后端还改进 WebDAV Range、OpenList 签名失效刷新、FTP 文件探测与缓存。它们主要由服务端生效，客户端重点验证 Range/HEAD、签名过期恢复、同源多挂载选择及字幕加载，不把后端账号解析复制到移动端。

## 6. 播放期鉴权恢复

上游 `lib/authTransport.ts` 新增 `isAccessTokenExpired()`；`sync-playback/hooks/useVideoSource.ts` 在非 B站播放期错误时尝试刷新 token 并按快照恢复。客户端已有 attach 阶段刷新，不能把它误当作播放途中续期已实现。

建议移植时收紧以下行为：

1. 只处理当前服务器鉴权相关的错误，保留 B站自己的过期/换源恢复链路；第三方 403、解码错误不能全当登录过期。
2. 单次刷新去重，检查刷新是否成功；失败转明确登录/重试提示，禁止无限重载。
3. 刷新前捕获房间、影片、源代次、进度、暂停状态与倍速，返回时校验仍属当前会话。上游示例通过当前 video ref 继续重载，移动端需要防止等待期间已换片/切服。
4. 重建主清单、分片和密钥请求时读取新 token；保留 HTTP、HTTPS、反代路径前缀、自签证书例外和游客场景。原生客户端的鉴权不可直接替换为上游网页的“HTTPS 只依赖 cookie”假设。

## 7. TVBox/CMS 与番剧数据源

### 7.1 用户可见链路

新增采集源入口：站点选择/全部站点搜索 → 详情与播放组 → 集数多选或整部加入 → 当前片单 → 实时解析 → 播放。复用已适配手机的 `AnimeSourceBrowser`、海报失败占位、滚动和集数选择能力。

上游 CMS 只支持 TVBox 配置中符合条件的 `type=1` 苹果 CMS JSON 采集站点；不是完整 TVBox JS/JAR 爬虫运行时。服务端负责拉配置、解析和缓存，双端不新增本地爬虫解释器。

| API，统一前缀 `/api/stream/cms` | 用途/返回 |
| --- | --- |
| `GET /sources` | 返回 `sources: [{id,name}]` |
| `GET /search?source=...&keyword=...` | 站点内搜索，返回 `results` |
| `GET /search-all?keyword=...` | 跨站点搜索；结果含真实 `source`、`vodId`，复合 id 为 `source::vodId` |
| `GET /detail?source=...&vodId=...` | 返回 `detail.playGroups` 及集数定位 |
| `POST /resolve` | 请求 `{source,params:{vodId,playFromIndex,episodeIndex}}`；返回 `url`、可选 `headers/format` |
| `GET /proxy` | 媒体中转入口；headers 与鉴权遵守既有代理隔离 |
| `GET /inspect?url=...` | admin/root 可检测配置；检测成功与配置保存是两个步骤 |

`sourceMeta` 保存 `{sourceId,vodId,vodTitle,playFromIndex,episodeIndex,episodeTitle}`；组/集下标按服务端 0-based 定位，不能拿显示集数替代。每次播放/恢复依据元数据重新解析，不能只保留短效 URL。

建议新增 `src/upstream/modules/cms/{types.ts,api.ts,CmsSelector.tsx}`，扩展 `roomStore.ts`、`MoviePushPanel.tsx`、`AnimeSourceBrowser.tsx` 和 resolver。管理员配置保留在服务端网页；若客户端没有管理入口，不为对齐协议新增整套管理后台。配置保存后重新读取 `/sources`，以真实可搜索站点为完成标准。

### 7.2 HLS 广告过滤与规则升级

上游 `hls-ad-filter.ts` 是对 CMS 代理清单的启发式过滤，不是完整 TVBox 广告规则执行器。加入 `/cms/proxy` 识别后，仅在对应文本清单上启用；不要全局套到 B站、媒体库或挂载直链。必须覆盖相对 URL、合法多 CDN、短清单、DISCONTINUITY、KEY、MAP 及误删恢复场景；错误过滤会改变时间轴和破坏解码。

Kazumi apiLevel 9 的 API 搜索/选集、JSONPath/模板、POST 抓取，以及 GBK 解码与解析缓存由新版后端提供。客户端检查搜索结果、播放组、字幕/格式字段及代理开关即可，保持现有自定义订阅。不要为跟进规则升级恢复之前排除的不可用默认源。

## 8. 播放器依赖迁移与移动端性能

上游现在使用 `frontend/vendor/playsvideo`（0.4.7 加本地改动），包括 worker 活动心跳和关键帧索引回传复用；`mediabunny` 固定源码提交并通过 `frontend/vendor/local-patches.mjs` 重放 DTS、FLAC 等补丁。客户端当前仍用 npm `playsvideo: 0.4.7` 与 `patches/playsvideo+0.4.7.patch`。

迁移不能只改版本号：

1. 对照客户端 patch 与上游 vendor 行为，逐项确认 MKV cue、音频时间轴、AAC/FLAC/DTS 修复是否保留；不要先删除旧 patch 再补功能。
2. 如采用 vendor，放入客户端 `vendor/playsvideo`，依赖改为 `file:vendor/playsvideo`，核对它引用的 `../mediabunny` 与客户端顶层解析到同一副本。同步锁文件、许可证与构建资源复制规则。
3. 对齐 `playsvideo-engine.ts`、`playsvideo-subtitle-bridge.ts`、`usePlayerSource.ts` 和 `useVideoSource.ts`。活动超时区分“仍在处理慢源”与“worker 已停止响应”，不能简单取消超时。
4. 接入 `probe/index/ffmpeg/seg0/decision/workers/segments` 进度，UI 展示对应可读状态；回调只存在本机运行时，不写入房间广播或持久化状态。
5. 接入字幕解析 worker、音频编码归一化与关键帧缓存。保留客户端 ASS/PGS 及多轨能力；worker、WASM 路径须同时适用于 Android assets 与鸿蒙 `https://zviewer.local`。
6. 在真机长时播放和 seek 中记录内存、起播/重载耗时、解码与实际声音。网页编译通过不能证明双端 HEVC、Opus、DTS 或后台行为。

上游同时升级若干 UI/构建依赖（例如 lucide-react 与 Vite 插件）；不要把服务端整个 package/lock 文件覆盖到 Capacitor 工程。按实际新增 API 需要分别迁移，保留客户端已验证的依赖组合。

## 9. 屏幕共享、P2P 与平台边界

- 新 `sharer-error` 由服务端校验房主后转发。双端需把采集拒绝、启动失败、发布失败映射为一致的失败通知和状态回收，观众结束等待；错误文案不包含 token、流密钥或私有地址。
- P2P 隧道新增 ICE 候选排队、`disconnected` 3 秒宽限及可观测错误；按 `src/upstream/modules/p2p/` 定向比较。STUN 列表的上游测试结果不代表用户网络可达，需要在实际网络检查，且不能与 LiveKit 语音通道混为一谈。
- 上游浏览器采集新增画质热切换、参数持久化和减少双路编码等优化。Android MediaProjection、鸿蒙原生采集已有各自质量状态和音频会话，不能整体换成 `getDisplayMedia` 或新增一个统计用编码连接。
- 浏览器 wake lock 只能作为可用时的前台辅助；双端常亮、前后台、锁屏和系统媒体策略须通过各自宿主验证，不能保证后台采集。
- OBS 的服务器地址与流密钥分别展示和复制，避免复制地址时自动拼上密钥；验证已有移动端复制行为后再移植。
- 保持 Android Activity PiP 与鸿蒙禁用 WebRTC PiP 的既有差异；共享代码不能把 Android 插件调用暴露给 ArkWeb。

| 必测场景 | 通过标准 / 证据 |
| --- | --- |
| Web 房主→Android/鸿蒙观众；双端轮流房主→Web/另一端观众 | play/pause/seek/rate/换片按权威状态收敛；没有双心跳导致的持续跳进度 |
| 延迟、丢心跳、丢 ack、重连、时钟前后偏移 | 自检可恢复；在途锁不会永久卡住；旧 ack 不控制新房间/新影片 |
| 房主离线后观众新加入、刷新、后台返回 | `hostOnline=false` 能保持自主暂停/seek；房主回来后恢复跟随 |
| 手动同步、从零播放、DASH/MSE seek | 强制同步有效；跳到零有效；失败按当前会话恢复，无旧源复活 |
| NCM/B站换曲、队列、FM、播放模式、服务端重启 | trackKey 正确，入队失败不推进，单个队列弹层，状态持久化恢复符合预期 |
| token 在播放中途过期、刷新失败与切服并发 | 成功后恢复进度/暂停态；失败有限重试；凭据不串服 |
| 直连/中转各测 MP4、HLS、MKV | 网络请求路径符合开关；媒体、子清单、key、Range 无暗中代理或 token 外泄 |
| HTTP/HTTPS/反代前缀/证书例外 | 双端 API、Socket、海报、媒体均走正确逻辑地址；撤销例外后恢复校验 |
| 同地址不同挂载账号、FTP 票据跨用户与过期 | `sourceMountId` 对应正确挂载；过期重新解析；不能跨用户复用 ticket |
| CMS 单站/聚合搜索、播放组/集选择、重新入房 | 元数据保持真实站点与下标；短效 URL 可刷新；403/空结果/超时有明确反馈 |
| HLS 过滤、多 CDN、字幕/音轨、长片 seek | 未误删正片或破坏密钥/时间轴；ASS/PGS、多音轨和声音实际可用 |
| 屏幕共享拒绝、失败、旋转、热切画质、后台 | 房主/观众状态一致；以接收端实际帧率/分辨率和音频为证据，不只看设置值 |
| 手机/平板、横竖屏、明暗主题、320px 窄屏 | 搜索、源列表、长标题、更多菜单及弹窗无重叠/横向溢出，返回路径正确 |

浏览器 fixture、桥接替身、原生模拟器、物理设备、真实跨设备网络必须分别标注。沿用 2.0.0 的历史结果只能证明历史版本，不能据此宣称新版通过。iOS 不在本次实施范围，不启动 IPA 构建。
