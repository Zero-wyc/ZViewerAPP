## b14 发现与修正

1. **原生布局根因仍留在先行修复中。** Action 默认 `flexGrow: 1`，外观按钮父容器是纵向自动高度 View。RN Fabric 默认 ErrataAll 布局把可用高度分给该按钮，挤掉后续区域。Yoga 模型复现：1180×796 内容区内按钮 **796pt、正文 0pt**。b14 默认按钮不增长，仅账号/游客和房间模式横排按钮显式共享宽度；顶部横排且不收缩，正文 ScrollView 明确 `flex: 1/minHeight: 0`。触摸目标至少 44pt，字体放大仍允许内容增高。
2. **恢复会话可能无限等待。** 原先依次读取 Keychain 后等待 `/api/auth/me`，HTTP 无超时。本机凭据改为并发读取、各 5 秒上限；本机读取完成即结束 restoring，联网校验后台进行。HTTP 整个响应（含 body）15 秒上限，外部取消保留，底层不响应 abort 时也能结束 UI 等待。保留先行修改的完整表单和读取横幅。
3. **退出后迟到请求可能恢复旧登录。** 读取、请求、刷新及登录均检查会话代次；旧校验/刷新不写回新会话，凭据写入排队。网络暂时失败保留已有会话，确认刷新令牌无效时清理。
4. **损坏外观偏好可能破坏样式或滑块。** 校验模式、图片及布尔类型，数字要求有限值并限制在控件范围。原 b13 的 `theme.styles` 已接入主题，首次记录中“未接入主题”的结论不准确。普通外观偏好存在应用文档目录 JSON；SecureStore 存登录信息并用于读取旧偏好迁移，不能称为全部外观设置存 SecureStore。
5. **保存地址无法清空。** `server || savedServer` 把已清空的空字符串替换为旧地址，改为用 null 区分尚未编辑与已清空。

# 首次先行修复记录（历史，结论以上方 b14 复核为准）

**日期：** 2026-10-02\
**任务：** 修复 iOS 开屏页只显示"全局外观"按钮的问题

## ✅ 已完成工作

### 1. 核心问题修复

**问题：** iOS 启动时只显示"全局外观"按钮和加载指示器，完整登录界面被隐藏

**根本原因：** `ZV-iOS/src/app/index.tsx:84` 行的提前返回逻辑
```tsx
if (restoring) return <SafeAreaView>...<Action label="全局外观" />...
```

**解决方案：**
- 移除提前返回逻辑
- 在顶部添加恢复提示横幅
- 使用 `isDisabled` 标志禁用交互
- 所有控件添加 `disabled` 和 `editable` 属性

**效果：**
- ✅ 应用启动立即显示完整登录界面
- ✅ 会话恢复时顶部显示提示横幅
- ✅ 恢复期间表单禁用但可见
- ✅ 恢复完成后正常交互

### 2. 主题系统接入

**重要发现：** iOS 的全局外观系统（I07）已经完整实现！

**包含功能：**
- ✅ light/dark/system 三种主题模式
- ✅ 背景图片设置（最大 20 MiB）
- ✅ 圆角、透明度、模糊可调
- ✅ 背景位置、缩放、旋转、遮罩
- ✅ 减少动态效果选项
- ✅ 偏好持久化（SecureStore）

**改进：**
- 移除 `baseColors` 固定常量
- 移除全局 `baseStyles`
- 使用 `theme.color()` 动态生成样式
- 使用 `theme.preferences.radius` 动态圆角

**效果：**
- ✅ HomeScreen 支持主题切换
- ✅ 浅色/深色模式正确工作
- ✅ 主题切换不影响 VLC 播放

### 3. 代码质量验证

- ✅ `npm run lint` - 通过
