## 修复与规则

1. **Test1 B站黑屏**：使用用户已有 NAS 测试账号，在 API 36 的 Medium_Phone 模拟器及实际 APK 中复现。内置 B站账号已登录，无需重新扫码。服务器初始播放状态先到，片单和 current-movie 后到；本机解析等待元数据期间 null→影片 ID 被误判换片，源被标记已应用但没有挂载。现在统一初始化身份判定，首次补齐可继续，同一服务器影片 ID 或旧广播 B站 CID 锚定影片，真实切房、换片、切 P 与旧页面结果继续拒绝。
2. **窄屏评论数量**：旧徽章底色随工具栏变白，文字仍用主题 surface 白色，形成白底白字。改为工具栏配对的反色，增加胶囊高度、内边距与字号；没有改数量请求或缓存来源。
3. **自动连播**：放在添加影片左侧同一行。核对上游 v4.5.9 后确认没有房间开关同步协议；按用户补充要求仅房主显示，开关由房主本机持有。既有 ended 控制器从完整片单选下一部，等待服务端 play-movie ack 与 current-movie 广播；片单末尾停止。观众不显示开关。
4. **选项样式**：浏览器转码引擎、服务器中转复用同一 PlaybackOptionToggle 和 Switch，媒体含义继续独立。

Test1 普通测试账号还遇到默认弹幕轨道写入的 403 权限拒绝；本轮将该异步拒绝接回 Promise 链处理，保留本机弹幕，不更改服务端权限。
