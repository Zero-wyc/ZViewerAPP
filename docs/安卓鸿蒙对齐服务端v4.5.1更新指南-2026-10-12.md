### 3.1 番剧浏览器与海报

1. 将源选择作为共享浏览器的 searchPrefix，搜索与选择行为使用同一状态模型；保留集数序号、线路和 sourceId，结果/集数数量大时内容区滚动、底部确认固定可达。
2. 只在搜索结果加载海报，集数页不用海报或上级目录；宽屏三列，窄屏按容器宽度保持触控和文字可读。上游窄屏默认单列，手机不能直接套固定桌面列宽。
3. 引入 `showParentDirectory`、`episodeGrid`、`preserveSearchTerm`、`searchOnSourceChange`、`renderPoster` 等适配参数；保持 Emby/Jellyfin 默认行为，不让番剧切源逻辑串入真实挂载目录。
4. 不用 `key={sourceId}` 重建 Modal。切源清理旧结果、集数、选择和忙态，保留关键词与客户端放大状态；重复选同一源不搜索，空白词不请求，输入文字不自动搜索。
5. 搜索、目录、源列表和批量添加各自检查请求代次、房间及打开状态。切源/离房/关闭/切服后旧响应不得写回，失败不得让 loading 永久挂住。
6. 单击集数只选择；确认才添加。沿用 `MoviePushPanel` 现有批量回调，返回成功集数 ID，失败集数留选、重试只补失败项；不要重复添加已成功的条目，也不要添加后自动播放。
7. 直连 cover 失败才尝试 `/api/stream/{kazumi|anisubs}/proxy?url=...&referer=...`；使用 `apiFetch` 取得 Blob，校验 image Content-Type，取消旧请求并 revokeObjectURL。失败占位不能挡住搜索或集数操作。
8. 图片组件复用时要按 cover/source 重置失败和 Blob 状态，防止 A 番剧旧图片挂到 B 番剧。切服时不能继续使用旧服务器代理图片。

### 3.2 Emby/Jellyfin 搜索、海报、整卡与版本

必须一起补齐下列信息，而不仅移植新 UI：

- `EmbyDirectoryEntry` / Jellyfin 对应类型：`indexNumber`、`parentIndexNumber`、`duration`、`filePath`、`recursiveItemCount`。Series 与 Season 仍可进入目录，同时提供整部/整季快捷添加入口。
- 搜索调用 `/api/{emby|jellyfin}/mounts/:id/search?term=...`，结果采用相同条目结构。返回目录时恢复合理面包屑，切换挂载时失效旧搜索与选择。
- 当前 `buildEmbyImageUrl` 在没有 tag 时直接返回 null，会阻止新服务端的文件夹封面回退。允许 itemId 无 tag 请求；tag 只作为可选缓存参数，URL 经选定服务器连接映射。
- 集号优先官方 S/E 字段，缺失才从 `filePath` 解析；Movie 类型但文件名能解析为分集时显示 EP 兜底角标。无信息时显示文件，不制造虚假集号。目录海报总数来自 `recursiveItemCount`，不是当前已加载条目数。
- `MountBrowser.onSelectFiles` 增加选中条目的完整 metadata，并增加 onQuickAddSeries；不能只传 path 后丢失 Series/Season 类型。
- 整卡添加枚举各季的 Episode/Video，保留每集 itemId 与 mountId，按返回顺序生成连续页码；解析首集建立一张影片卡。多集单独添加与整卡添加必须有明确不同入口，不把“全选”悄悄变成“整部”。
- pages 增加可选 `path`、`mountId`；同时更新 `BilibiliVideoPage`、`MovieDto`、映射函数、addMovie/updateMovie 请求类型，保留 B 站 `epId`、`badge`。当前客户端切页先进入 B 站逻辑，必须在前面分流 Emby/Jellyfin。
- Emby/Jellyfin 切集先 resolve 目标 itemId，再更新 `movie.path`、`url`、`format`、`duration`、`currentPage`。代理模式用按 movieId 的 stream URL；URL 可附 ep 标识触发重载。直链模式使用新鲜 directUrl，不保留旧集 token。
- `EmbyResolvedSource`、Movie/DTO/请求增加 `multiVersion`；版本数据包含 `versions`、`mediaSourceId`。从 `/api/{api}/movie-source?movieId=N[&ms=X]` 懒加载并选择，单版本隐藏选择器，不能据分辨率文本猜版本 ID。
- 切版本同步更新 URL、format 和音轨信息，防止 HLS/音频转码被错误当作旧 MP4。保留媒体缓存失效、旧实例销毁和 seek 恢复边界；快速切集/切版本、离房后的旧解析必须失效。
- 观众播放使用房间影片 ID，不能要求观众有房主私人挂载列表，也不能广播房主的设备私有回环地址。真实切页/切版本后应同时验证普通浏览器观众。
- 图片代理在显示时映射选定连接；写入 Movie.cover/url 前保留逻辑服务器地址，必要时使用 `logicalConnectionUrl` 剥离私有通道。不能把设备回环图片 URL 当作房间可共享封面。

1.7.3 的单集 16:9 图片、剧集/季 2:3 图片、全选/取消全选、按原顺序添加、切目录清空选择，以及放大后目录随 flex 增高，均作为不可回退的验收项。

### 3.3 一键清除与权限

- 新增 `roomStore.clearMovies(roomId)`，调用 `DELETE /api/rooms/:roomId/movies`，检查 HTTP 状态及 `{success, removed, message}`。一次请求清整个房间，不循环删除，不仅删除搜索可见项。
- 最新后端实际条件为 `role === 'root'`，或 `role === 'admin'` 且 `room.ownerUserId === 当前 userId`，不能仅凭“当前房主/房管”标签认定有权。沿用客户端已用于片单排序的真实角色/创建者判断，并以服务端 403 为最终结果。
- 当前客户端仅在展开片单时为管理员查询 owner；若主卡片也提供清空按钮，应同步完善 owner 加载的触发与缓存，不能让入口必须先展开一次才能显示。
- 主影片列表与展开窗口共用入口；沿用上游二次点击确认，并清楚表达“清空全部影片”。空列表、断开连接、投屏及请求中禁用/隐藏，阻止重复提交；失败保留列表和播放状态。
- 成功后清搜索、选中与当前影片；权威列表通过 movie-list 更新，current-movie 为 null 时停止旧视频/音频和自动连播，取消待执行切集、解析及缓存回调。手机不能因忽略 socket 的 null 状态而继续播放已清空影片。
- 清空请求记录原房间和连接代次，响应晚到时不能清掉新加入房间的当前影片。管理员/创建者退出、普通观众调用及切房均需要独立验收。

### 3.4 B 站、公告及辅助行为

- B 站搜索点击后显示分 P 并确认添加，继续使用客户端本机 Go/ArkTS 解析、短链展开、PGC ep 定位、账号会话与 cliOnly 边界；不能直接照搬桌面服务器解析绕过这些限制。搜索关闭/重开、分页与旧请求处理保留。
- 公告公开设置新增 `announceAutoPopupOnUpdate` 与服务端 `appVersion`。已读记录按逻辑服务器地址隔离，不能把 APK/HAP 版本号当服务端版本；升级提示受管理员开关控制，用户首次读取行为单独处理。
- 公告按上游读取公开 announce.md；访问 GitHub 等第三方地址不附带 ZViewer 的 Authorization/Cookie。外链使用现有外部打开能力，不放开 ArkWeb 任意导航。公告失败不妨碍登录和入房。
- 音量拖动处理 pointerup、pointercancel、卸载、页面进入后台等退出路径；恢复拖动前滚动状态，避免与已打开 Modal 的锁冲突，保持音量为本机状态，不向房间广播。
- 挂载目录主要是服务端修复：验证 `/videos`、中文目录、无尾斜杠、FTP 相对配置的归一化及重新打开浏览器。不要在 App 里再加一套取父目录补丁。
- 房间名同步和 Rolldown/dash.js 补丁当前已具备，仅回归。桌面首页、管理页排版与头像图标微调不必逐个照搬；按 App 自有入口判断是否有对应功能。

## 4. 双端平台边界

### Android

- 共享业务在 `src/upstream/` 与 `src/mobile/`；Capacitor 壳为 `ZV-Android/`，原生入口继续经 `src/platform/`。
- 新 REST 操作统一经 `apiFetch`。媒体/图片地址通过 `getApiUrl()` 和 `connectionTransport`：当前 getApiUrl 已返回选定连接通道，不要手工重复拼私有前缀。
- 图片 Blob 回退、搜索、清空及切版本都应覆盖 HTTPS Cookie、HTTP Bearer 和选定服务器证书例外；不增加全局证书放行。
- 保留现有 B 站本机代理、原生媒体控件、旋转、安全区、生命周期与音频路由。新界面不要求新增原生能力；只有实际发现契约不足时再改 Java/Go 桥。

### HarmonyOS

- 保留 ArkTS B 站解析、音频会话、后台/系统媒体控件及既有 HEVC Main 10 限制。海报、搜索等变化不能被解释为新增解码能力。
