# 房间界面动态字体与双向转交

2026-10-22，NAS 4.7.4，专用音乐验收房，iPad Pro 11 M5 / iPadOS 26.5 与 iPhone 17 Pro / iOS 26.5 Simulator。使用第 11 次成功 Debug 原生构建及本轮 Metro 调试代码；这不是发布包或跨 Android / HarmonyOS 验收。

## 动态字体

初次在运行中将 Device Hub Text Size 从 3 调到 6，iPhone 房间面板多处文字末尾被裁；相同字号冷启动后完整显示。因此未用关闭字体缩放掩盖问题。

`FontScaleProvider` 记录到真实 `fontScale` 为 `1 → 1.353`。`DynamicText` 仅在倍率变化时重建原生文字段落；房间、弹窗、输入框与播放器组件保持挂载。

- iPhone：房间面板保持打开，实测 `1.353 → 1 → 1.353`，模式、外观、连接状态、房间 ID 和离房操作均完整可见。[放大字体实际界面](ios-simulator-2026-10-22/16-iphone-room-large-text.png)。
- iPad：名称编辑中输入未提交草稿，执行同样字号往返，输入仍为原草稿。键盘弹出时输入、确认 / 取消、弹窗关闭和底部离房操作可达。随后取消草稿，房间名称保留原值。
- 以上只覆盖已列页面与操作；其他来源页、字幕长文、横屏短高度和真正分屏仍须分别验收。

## 房主双向转交

服务端在事务中交换会话角色，但 `host-transferred` 只发新旧 Socket ID 与新 owner，不另发 viewer joined / left。原实现只改房主身份，导致新房主保留自己的旧观众记录、无法从成员列表转回。

现在按权威转交事件调整成员集合；只复用相同 Socket 的已知身份。未知姓名显示“原房主”，不猜用户 ID 或系统角色。重复事件幂等，拒绝相同新旧 Socket；缺少旧字段时不凭空添加成员。确认弹窗显示具体对象。

约北京时间 18:58，在两设备持续连接期间，实际完成 iPad 账号 1 → iPhone 账号 3 → iPad 账号 1：旧房主的管理与切模式入口退场，新房主立即获得管理入口、能对原房主再次转交。最终 iPad 恢复房主，成员数为 1。没有靠重连刷新名单。

六项集合转换 / 身份隔离回归和房间设置针对性检查通过。房管与普通账号权限、被踢 / 审批等仍按总验收清单单独记录，不能由这次双向转交代替。
