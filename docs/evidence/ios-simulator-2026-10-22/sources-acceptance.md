## 本轮阻塞和异常的归属

1. **AniSubs 上游解析不可用**：10 个现有来源都已尝试，取得分集的所选媒体解析均 404。请求使用服务器返回的实际 episode / playbackParams；不修改 NAS 订阅或补造可播地址。需有可用上游素材或单独处理服务端提供者后，才能完成正向播放验收。
2. **NAS REST / Socket 片单曾不一致**：59 / 60 已在 REST 存在，原生 `play-movie` ACK 却报影片不存在；仅向专用影片 PUT 原值 false 后，59 重试成功。参考源码的 POST / PUT / register-host 都应同步 DB 片单，因此当前只记录部署运行时现象，未判定根因，未声称通过客户端修好了服务器。
3. **测试素材边界**：当前账号无 Emby 挂载；三个 Jellyfin 候选均单版本；没有为验收新增挂载或改变 NAS 配置。缺少的环境场景保留为未验，而不是以单一成功样例覆盖全部要求。
4. **CMS 返回网页 / 拒绝响应**：28 个来源各完成一轮搜索，取得地址的候选均未通过实际媒体前段检查。解析成功只表明服务器返回 HTTP URL；本轮 62 的 403 HTML 和代理 206 HTML 均不能进入“媒体可播”结论。没有通过播放器网页抓取或修改 NAS 配置绕过。

## MKV 暂停 seek 参考帧复核

66 的暂停截图虽显示 137.207 秒并保持稳定，主体却几乎全灰，不能只凭时钟记 seek 通过。同一原始 NAS MKV 使用既有 ffmpeg-static 在 137.207 秒抽取一帧，实际为清晰彩色画面，和截图不符；因此本次画面定位失败，原因仍待原生专项定位。抽帧只运行 2.966 秒，17 次 Range、读取 13,877,233 字节，设置 45 秒 / 32 MiB 硬界限，没有下载整片。脚本、认证和原始 stderr 均留在仓库外权限 600 的文件；参考原片帧也留在仓库外，本目录仅保留脱敏统计。

67 的[不同账号 iPhone 画面与 ASS 字幕](15-mkv67-iphone-ass.png) 已目视核对后归档；它不证明 66 seek、67 seek 或声音听感通过。

## iPad 窗口修复（第 10 轮已安装，真实窗口待验）

第 9 轮的 `ios.requireFullScreen=true` 不能满足 03 的真实分屏与窗口动态 resize。Apple 对这个兼容模式的说明指出，传统 Split View 可能被排除；新窗口模式也可能仅缩放固定 scene，而不是向应用交付动态尺寸。[UIRequiresFullScreen](https://developer.apple.com/documentation/bundleresources/information-property-list/uirequiresfullscreen)

本次已将 `app.json` 改为 `requireFullScreen=false`，由持久 scene 插件声明 iPad 四方向、iPhone 原 DEFAULT 等价三方向，移除 Expo 通用初始方向掩码，保留单 scene / 单 React Native 根。`usePlayerDisplay` 在 iPad 使用当前 window bounds、监听窗口变化，原生 lock / unlock 均不发出，能力与锁状态保持 false；方向入口说明“方向由系统窗口管理”。iPhone 仍沿用实际视频尺寸驱动锁向。Expo SDK 57 的锁向 Promise 不能作为系统旋转成功证明，因此没有在 iPad 冒报锁定成功。[Expo ScreenOrientation](https://docs.expo.dev/versions/v57.0.0/sdk/screen-orientation/)

第10轮已prebuild、确认Info.plist并构建安装；实际拖动手柄未发生window尺寸变化，不计分屏 / resize通过。仍须实测窄 / 宽窗口、全屏填满当前窗口、键盘与来源页130%字体、同一播放器实例持续播放及iPhone横竖切源。先前50项定向回归通过；面包屑新增2项，相关两文件19项通过（与前50重叠）；库路由 / 身份四文件39项为补证。完整check14为355 / 355；不把重复数字相加，也不代替原生窗口验收。Apple建议迁出旧全屏兼容模式并适配可变窗口；方向锁偏好仍可能被系统拒绝。[TN3192](https://developer.apple.com/documentation/technotes/tn3192-migrating-your-app-from-the-deprecated-uirequiresfullscreen-key)
