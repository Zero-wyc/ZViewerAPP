## 2. 客户端已确认缺口

### C01：Emby/Jellyfin 一起看封面没有完成跨设备地址规范化（对应 S01）

源码入口：

- [`buildEmbyImageUrl`](../src/upstream/modules/emby/embyApi.ts#L11)：使用当前 API 基址生成绝对图片代理地址。
- [`MoviePushPanel`](../src/upstream/modules/room/components/MoviePushPanel.tsx#L597)：整剧和单文件入列用 `logicalConnectionUrl` 去掉原生通道，但保留下发者的访问域名。
- [`logicalConnectionUrl` / `connectionUrl`](../src/platform/connectionTransport.ts#L12)：只转换当前绑定的逻辑 origin 与通道，并不代表同服务端的所有旧访问地址都可转换。
- [`systemArtworkUrl`](../src/mobile/useSystemMediaSession.ts#L14)：调用的音乐封面处理只对 B站已知图片代理和网易云做相应转换；Emby/Jellyfin 的旧地址保持原样。
- [`WatchTogetherCore` 系统媒体快照](../src/upstream/modules/room/watch-together/WatchTogetherCore.tsx#L1551)：将 movie.cover 传入该函数。

本轮直接加载实际客户端函数，在当前查看者为公网域名、原生连接为新的 localhost 私有通道时，得到：

| 输入 | 实际输出 | 判断 |
| --- | --- | --- |
| localhost 下的 `/api/emby/mounts/1/image` | 仍为同一个 localhost 地址 | 其他设备请求自己，地址未修复 |
| 另一个仅 LAN 可达域名下的 Jellyfin 代理 | 仍为那个 LAN 域名 | 公网查看者不会自动改走自己的连接 |
| 旧原生端口和通道下的 Emby 代理 | 仍为旧端口和旧通道 | 重连后可失效 |
| 新建 Emby cover 经 logicalConnectionUrl 入列 | 保留添加者的绝对逻辑地址；另一域名查看时不变 | 仅剥离通道不足以解决跨访问域名 |
| 同轮输入旧 B站 proxy-image | 正确改用当前查看者的新通道 | 前轮 B站修复仍有效，不应撤销 |

结论是条件性封面缺口，主要关联一起看系统媒体封面；没有将所有播放卡片或所有真机都判为必现失败。

修复方案：

1. 与服务端定义可移植的海报资源身份/端点，存储和广播阶段不保存设备私有端口、通道、令牌或仅当前网络可达的访问 origin。
2. 展示、视频系统媒体、音乐系统媒体分别在使用时取得当前连接，不能只对音乐播放器补函数。Emby/Jellyfin 海报按服务端 S06 的授权能力合同获取。
3. 历史兼容只处理已确认属于本服务端的图片代理；不要将任意外部域名的 `/api/...` 资源重写到自己的服务器，也不要把真正的 CDN 图片误改成 Emby 请求。
4. 证书例外连接必须使用已经建立的安全通道；系统媒体原生获取图片的路径也要检查，不能仅验证 WebView img 的 DOM 地址。
5. 不批量重写用户库、不重签整个播放协议，尽量在入列规范化和读取/使用边界处理兼容。

验收：网页 localhost→Android/HarmonyOS；手机内网地址→另一端公网地址；路径前缀、证书例外、重连换通道、Emby/Jellyfin、旧队列、单片/整剧、系统通知栏和锁屏。须分别记载 Android 与 HarmonyOS 的实体设备结果，不能用浏览器或原生桥桩的成功代替。

### C02：部分网易云图片入口仍绕过统一处理（网页与双端均有）

源码确认：

- [`MusicTopNav`](../src/upstream/modules/music/components/MusicTopNav.tsx#L916) 和同文件第二个账号头像直接 `src={loginStatus.avatarUrl}`；[`useNcmLogin`](../src/upstream/modules/music/hooks/useNcmLogin.ts#L151) 将上游头像原值存入登录状态。
- [`AddToPlaylistModal`](../src/upstream/modules/music/components/AddToPlaylistModal.tsx#L382) 用原始 `coverImgUrl + '?param=90y90'`。
- [`NcmSearchModal`](../src/upstream/modules/music/components/NcmSearchModal.tsx#L403) 用原始 `song.cover + '?param=80y80'`。
- 服务端仓库网页中的同名组件也保留相同写法，不是 Android 或 HarmonyOS 原生桥独有问题。

若上游返回 HTTP 图床地址，这些入口没有获得已存在的网易云 HTTPS 规范化；若地址已有查询参数，字符串再拼 `?param=` 不会正确替换尺寸参数。实际是否被阻止/图片是否仍显示取决于运行时与 CDN；本轮不将它们写成全部真机已复现白图。

修复：在这些渲染入口使用已有 [`neteaseImageUrl`](../src/upstream/modules/music/utils/neteaseImage.ts) 及既有错误回退，保留非网易云来源语义。统一通过 URLSearchParams 替换尺寸，保留其他有效查询，不增加另一个近似但不同的图片工具。不将一次图片加载失败解释为音乐登录失效。

验收：HTTP/HTTPS/协议相对地址、已有 param、其他查询、空头像/坏图、两处账号头像、歌单选择弹窗、搜索弹窗；在服务端网页和双端共享 UI 各验证一次。

## 3. 服务端各问题对应客户端影响

编号与服务端报告一一对应；“客户端无直接代码修复”表示根因必须在服务器处理，不表示该问题不影响使用。

| 服务端编号 | 客户端表现/关联 | 客户端应如何配合 |
| --- | --- | --- |
| S01：影片封面地址 | localhost/旧通道/添加者网络地址留在 cover | 按 C01 同步修，展示与原生系统媒体都绑定当前查看者连接 |
| S02：OBS 转发域名 | 导出的推流服务器可能为 localhost，另一电脑导入后连自己 | 以服务器明确返回的发布入口为准；不能在手机端随意把 localhost 替换成网页域名。网页可达与 RTMP 可达应分开说明 |
| S03：RTMP IPv6 | 生成的无方括号 IPv6 推流 URL 无效 | 保持合法 IPv6 URL，避免再按冒号切分主机；下载配置功能覆盖 IPv6 样例 |
| S04：代理 302 | 图片/音视频流得到 302 空正文且无 Location，可能反复加载 | 服务端修重定向；前端错误提示与有限重试，不增加“无限换代理/无限跳歌”。视频、音乐和系统封面都需验证 |
| S05：推流能力泄露 | 待审批阶段就获得媒体码，UI 挡按钮没有保护效果 | 待审批不得连接媒体；采用新的受限观看票据；OBS 发布凭证只给获准发布者。同步修改相关响应类型、共享模式切换和退出/踢出清理 |
| S06：匿名海报授权 | 简单给图片接口加登录校验会使 img/系统媒体失效 | 按协商的签名图片能力或受认证取图方式接入；保留后台和原生封面可读性，不把挂载 API Key 放进 URL |
| S07：服务器文件可按路径读取 | 当前播放请求可能使用路径型端点，授权收紧后出现 403 | 迁移到有影片身份/受限能力的播放 URL；普通观众不依赖管理目录接口，root 文件管理保留合法能力 |
| S08：真实文件根逃逸 | 纯客户端路径校验无法判断服务端 junction | 后端处理；客户端展示拒绝信息，不用去掉路径限制或反复改写路径重试 |
| S09：头像主动内容 | 前端文件选择 MIME/后缀限制能被绕过 | 保留客户端限制，但后端内容验证才是修复。现有共享移动界面不等于完整个人头像上传功能；不得声称仅改文件选择器已解决 |
| S10：任意回环媒体代理 | 当前媒体路由可能经通用代理，不能简单封掉所有 NAS | 已授权 NAS 使用影片/挂载专用入口；错误不退回无授权通用代理，也不把他端 localhost 当自己的可用源 |
| S11：挂载选择错配 | UI 选择第二个同址挂载，服务端仍可能选第一个账号 | 发送真实选中 sourceMountId，处理服务端归属拒绝；不要回退成“只传 serverUrl”以掩盖错误 |
| S12：REST/Socket 不一致 | 当前双端 roomStore.addMovie 走 REST，正常添加可被保护；其他 Socket 客户端仍能写坏记录 | 保持 REST 创建路径；兼容读取服务器已有坏记录时按规范合同恢复，不能据本轮测试宣称双端正常路径必现此故障 |
| S13：重复 RTMP 发布者 | 流在旧发布者退出后消失，观众仍在等/重连 | 服务端作发布代次保护；客户端只作有限重连和状态提示，不能将“连接仍在”视作媒体仍可用 |
| S14：字幕越过影片范围 | 获准观看一部影片不应获得整个根/挂载的浏览读取权限 | 普通观众只读已授权字幕；房主跨目录选字幕走明确关联合同，既有字幕内容同步不能因收紧目录权限消失 |
| S15：本地字幕超限 | 超大正文可能进入 WebView 解析或广播 | 对超限 code 显示明确提示；保留上一字幕，不解析/广播失败结果，不通过另一旧端点绕过限制 |

R01 CORS 策略如果收紧，须覆盖 Capacitor、本地原生通道、HarmonyOS 与自定义网页地址，不能统一关闭跨域。R02/R03 的目标校验、响应上限和连接复用由后端承担；移动端不应靠放宽网络安全配置补救。R04 外置 LiveKit HTTPS 兼容边界和 R05 首次管理员初始化属于部署/服务端工作，本轮没有改动双端语音协议或账号策略。

## 4. 建议的客户端修改边界

### 4.1 封面必须分开“存储身份”和“当前取图地址”

保留已有 B站原图元数据规则；Emby/Jellyfin 保存受信资源身份，实际取图时再使用当前逻辑服务器与原生连接。原生通道路径属于当前连接的私有能力，不能持久化或分享给另一端。

签名图片能力应能短期刷新，不能把很快过期的 URL 当永久封面写入队列。图片授权与音频/视频授权分离；不要让获取一张图触发整个 App 登录重置。

### 4.2 新权限错误不能破坏已有登录和播放恢复

当前 [`apiFetch`](../src/upstream/lib/api.ts#L356) 已把普通 403 当业务拒绝，`AUTH_FAILED` 的上游 401 也避免刷新 App；音乐请求已有错误保留和扫码生命周期保护。后续服务端新增房间/文件/图片能力错误时要延续这些规则：

- 403 表示本次资源准入失败，按房间状态提示重新入房/申请，不自动换身份或旧代理重试。
- 上游 NAS 账号错误、NCM 不可用和图片能力过期分别处理，不能清掉用户本次输入的服务器用户名/密码。
- 资源票据过期允许受控重新取得；退房/切服/失去权限后到达的旧响应不得恢复播放。
- 失败后保留已确认的队列、旧字幕和本地设置；不要用伪成功空数据覆盖。

### 4.3 平台差异

| 平台 | 后续重点 | 本轮证据 |
| --- | --- | --- |
| Android | WebView 取图通道、PlaybackService 封面下载、系统通知栏/锁屏、证书例外和后台播放 | 实际共享 JS 函数 + 76 项维护回归；没有新增真机/安装包证据 |
| HarmonyOS | 原生连接通道、AVSession 封面、后台 Web 引擎租约、网络/证书例外 | 同上，不能把 Android 原生行为推定为 HarmonyOS 行为 |
| iOS | 独立 React Native 代码，需另作资源 URL、图片鉴权与媒体控件对照 | 本轮未全量审查、未改动、未构建；不能写为已完成适配 |
