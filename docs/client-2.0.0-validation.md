## 构建与发布

共享源码依次执行 `android:sync` 与 `harmony:web`；生成资源不手工修改。Android Gradle `assembleDebug assembleRelease`、HarmonyOS Hvigor Release `assembleHap` 从最终源码新构建成功，版本均为 2.0.0/200。

- APK 通过 `apksigner verify`，HAP 通过 `hap-sign-tool verify-app`；双端发行证书均与 1.9.5 一致。APK 包内版本 200/2.0.0，HAP `module.json` 同为 200/2.0.0。
- APK 的 32 个网页资源、HAP 的 30 个网页资源逐字节匹配各平台最终同步目录；没有使用追加下一部功能前的旧安装包。
- Medium_Tablet 已覆盖安装最终正式 APK 并冷启动成功；Medium_Phone 已覆盖安装最终 Debug APK 并冷启动成功。手机模拟器原 `com.zviewer.mobile` 使用不同测试签名，正式 APK 覆盖被系统拒绝，保留原数据；该情况与已验证匹配的 1.9.5 发行证书分开记录。鸿蒙此次 UI 使用已安装调试宿主验证，最终 Release HAP 未再次通过 HoKit 安装，不把签名成功写成安装成功。
- 最终文件位于 `release/client-v2.0.0/`：APK 76,745,168 字节、HAP 14,253,044 字节；构建后各计算一次 SHA-256，保存 `SHA256SUMS.txt` 和本地发行元数据。上传与发布读取已存摘要，不重新计算安装包摘要。

本地提交后将源码推送 main，建立 `client-v2.0.0` Release；资产只有新版 APK、HAP、SHA256SUMS.txt。密钥、签名配置、账号、原始设备日志与 AGENTS.md 不进入公开源码，源码压缩包由 GitHub 自动生成。复杂公网 NAT/TURN、实体 Android 硬件音质及长期热量耗电不在本轮通过范围内。
