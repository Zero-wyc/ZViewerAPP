## 原生运行时

以下观众端场景由本地 Socket 房主驱动，媒体在安装包内的真实播放器解码；未向播放器注入桥接/媒体替身。双端轮流作为房主的完整跨设备矩阵尚未覆盖。

### Android

最终源码重新构建 Debug/Release，Debug APK 覆盖安装在 Medium_Phone 模拟器（API 36）。本轮测试直接运行 APK 内的共享业务代码，连接隔离的真实 v4.5.9 服务端及 60 秒 H.264 测试视频，而非向页面注入播放器替身。

实播得到 640×360 解码画面和持续视频帧；play/pause、15 秒跳转、1.5 倍速、全量同步到 0、房主离线后保持自主暂停通过，测试期间没有新 JavaScript 运行异常。首轮曾复现“离线后暂停被缓存在线状态撤销”，增加离线事件保护后重新同步资源、构建、安装并独立重跑通过。中间包不作为交付包。

### HarmonyOS

Pura 90 Pro x86_64 模拟器，OpenHarmony/HarmonyOS 7.0.0 / API 26，安装本轮签名 Debug HAP。直接运行包内 ArkWeb 客户端，连接同一隔离 v4.5.9 服务端和 60 秒 H.264 视频；得到 640×360 解码画面和视频帧推进，play/pause、15 秒跳转、1.5 倍速、全量同步到 0 及房主离线后自主暂停通过，测试期间没有新 JavaScript 运行异常。

本机工程最低 SDK 仍为 6.1.0(23)，本轮模拟器 API 26 不能代替 API 23 真机验收。正式 Release HAP 的签名/资源检查与 Debug HAP 的运行时结果分别记录，不将前者写成真机安装通过。

冷启动复查另复现原生安全区监听早于 Web 绑定导致 17100001 异常并退出。Index.ets 增加页面就绪/存活守卫，兼顾销毁期间的同步异常和迟到桥响应；此项单独重建 HAP，连续 3 次冷启动通过且没有新增崩溃记录，随后重新执行上述实际视频播放与同步场景通过。

两个模拟器始终轮流运行，每次确认前一模拟器退出后再启动另一端；未同时启动两个模拟器。
