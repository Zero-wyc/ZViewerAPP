# 安卓内置 CLI：登录后自动最高画质方案

状态：待实施。基于本地 ZViewerCLI-4.1.2 和 ZViewer-client 代码分析；本文件不代表已经完成安卓适配或真机验证。

## 1. 对齐后的产品规则

用户在客户端完成 B 站账号登录，且内置代理就绪后，默认启用“自动最高画质”。每次开始播放 B 站视频或切换分 P，客户端选择该账号对当前视频有权限、存在实际播放轨道、且当前设备支持播放的最高画质。

“最高”按分辨率和同分辨率下的画质档位决定，不是固定请求 1080p 或 4K，也不是简单取最大的 qn 数字。HDR、杜比等特殊档位要单独验证设备及播放链路能力，不能只凭 qn 数值认定优于其他档位,选择时默认不选择HDR与杜比世界。

如果没有可播放的 1080p 及以上画质，或最高画质经有限重试后仍不能播放，优先选择 720p。只有当视频或账号实际也不提供 720p 时，才使用可用的更低画质，并显示实际结果；没有任何可播放地址时提示错误，不显示虚假的“720p”。

登录成功会将默认策略设为“自动最高”。用户随后手动选择画质时，以手动选择为准；再次选择“自动最高”才恢复自动模式。登录不会改变账号本身的观看权限。

## 2. 用户体验

1. 在客户端的“B 站账号”入口完成登录，Cookie 留在原生侧。
2. 登录成功并确认代理可用后，显示“已登录，默认自动最高画质”。
3. 播放器画质菜单增加“自动最高”选项，同时显示实际画质，例如“自动最高 · 1080p”。
4. 自动回退时显示一次简短提示，例如“高画质播放失败，已切换至 720p”。
5. 用户手动选择 720p 后，本片及其分 P 保持手动策略；换到另一影片恢复默认自动最高。切回之前影片时可以保留其本次观看的手动策略。

正在播放时首次登录：若本片处于默认自动模式，登录成功后仅触发一次重新解析，保留播放进度和暂停/播放状态；若用户已经手动选了画质，则保留其选择。避免登录、代理重连、房间广播连续触发多次切源。

## 3. 自动选择流程

```text
开始播放 / 换片 / 切分 P
    ↓
是否存在本片手动画质选择？
    ├─ 是：按手动策略解析，失败时提示并恢复原可播放源
    └─ 否：进入自动最高策略
              ↓
         B 站登录有效且本机代理就绪？
              ├─ 否：使用现有服务器解析，优先请求 720p
              └─ 是：发现当前视频可用画质及实际轨道
                         ↓
                    排除无权限 / 不存在 / 设备不支持的轨道
                         ↓
                    选择最高可播放画质
                         ↓
                    有 1080p 及以上候选？
                         ├─ 否：优先 720p，否则可用更低画质
                         └─ 是：请求播放源并验证实际返回轨道
                                    ↓
                               播放成功：显示实际画质
                               播放失败：有限恢复 → 720p
```

服务器回退同样受服务器账号权限和视频可用画质影响，不能保证未登录时一定取得 720p。内置代理恢复且账号有效后，可在下一次播放时重新执行自动最高；本片已经回退成功时不反复自动升降。

## 4. 解析层的实现

在 CLI 核心增加显式策略，例如 `qualityMode=autoMax|manual`、`fallbackQn=64`，手动模式保留现有 `qn` 参数。移动端自动模式不能继续沿用 `qn=0` 的固定默认规则。

自动模式采用“发现候选 → 选择 → 必要时重新请求”的过程：

- 根据登录状态和视频信息请求画质列表及 DASH 轨道，必要时请求目标档位获取完整候选；不能把一次受请求参数限制的响应当成全部可用画质。
- `accept_quality` 只用于发现候选。候选必须同时满足账号权限、可取得实际轨道及设备播放能力。
- 设备能力由前端/原生层提供。以 MIME、编码、分辨率、帧率等筛选，并以实际播放器加载结果验证。同画质优先使用兼容的编码及普通 AAC 音频，特殊视频或音频轨道另行验证。
- 常规档位使用明确的优先级表；720p 对应当前协议的 `qn=64`。特殊档位单独判断，接口返回的名称作为展示参考。
- 返回的 `currentQn` 必须对应最终所选轨道的 ID，不得把请求 qn 当作实际画质。
- 建议响应增加 `qualityMode`、`requestedQn`、`selectedQn` 和 `fallbackReason`，用于界面展示和问题定位。
- 自动最高默认走 DASH 流式播放。若本片明确选择了 MP4 或整片缓冲模式，需要在设置中说明其限制，不能为了最高画质悄悄改变用户明确选择的播放模式。

当前代码需要调整的地方：

- `resolver.go` 的普通账号默认 qn 为 80、会员默认 qn 为 120，并非自动最高。
- 当前权限失败处理会从高画质降到 qn=32，需要为自动模式优先增加 qn=64 的回退。
- `normalizePlayUrlData` 在没有匹配 qn 轨道时会从其他轨道选择，但仍可能保留原 qn；应依据最终选中轨道修正实际画质。
- `computeFnval` 按目标画质设置发现参数，自动模式需要验证能否发现账号实际可用的更高档位，特别是目前只在请求 8K 时启用对应标志的情况。
- 统一 `/resolve` 的参数、实际画质及错误字段契约。

## 5. 失败与回退

不能把所有卡顿都当作高画质不可用。自动回退只针对明确的权限、轨道、编码不兼容，或在规定次数内无法恢复的网络/加载失败。

建议首版恢复预算：对同一画质最多执行一次有效恢复。CDN 连接失败先尝试已有备用地址；地址过期先重新解析；明确不支持的编码直接排除。同一播放任务必须有总超时，耗尽预算后进入 720p 回退。

选择最高候选前的能力筛选允许跳过不支持的高档位，例如设备不支持 4K 时直接选择可播放的 1080p。已经选择的最高候选发生运行时失败并耗尽恢复预算后，按产品规则直接尝试 720p，不再逐档反复尝试。

720p 回退也必须验证真实轨道及播放结果。若不可用，再尝试实际可用的更低档位；仍失败则提示原因。会员内容、地域限制、视频删除等不可通过降低画质解决的错误应直接提示，避免重复请求。

暂停状态、自动播放被系统阻止、房主暂停、正常 seek，以及短暂缓冲，都不应触发降画质。自动模式失败候选在本次视频观看中暂时排除，防止反复切换。

## 6. 客户端与房间同步

平台层提供内置代理的就绪状态、实际端口和 B 站登录状态；安卓优先使用本机实例，不以服务器上的代理列表判断本机可用性。

画质策略、实际画质和失败候选按当前设备保存。房主和观众分别使用自己的账号及设备选择画质，房间继续同步影片、分 P、进度和播放状态。房主切换画质不应覆盖观众的自动或手动策略。

现有 `useBilibiliQuality.ts` 和 `useVideoSource.ts` 可复用，但需要区分房间状态中的画质与本机实际画质：播放器菜单以本机最终轨道为准。本地代理地址与会话凭据不能作为其他设备可用的播放地址广播。

缓存键增加账号会话版本、影片/分 P、画质模式、手动 qn、设备能力和代理实例标识。登录、退出、账号切换及权限变化时使相关缓存失效，避免沿用旧账号解析结果。不要把 Cookie 本身作为可输出的缓存键。

## 7. 实施顺序

1. 完成 Go 核心的 Android AAR 封装、原生桥接和本机代理生命周期。
2. 实现自动最高解析策略、实际轨道校验及 720p 回退。
3. 接入登录成功事件、画质菜单、手动优先规则和缓存失效。
4. 验证房主/观众独立画质与进度恢复，完成真机播放测试后再发布 APK。

## 8. 验收标准

| 场景 | 预期行为 |
| --- | --- |
| 已登录，视频可用最高为 1080p | 自动播放 1080p，菜单显示实际画质 |
| 已登录，账号和设备支持更高画质 | 自动播放该视频实际可播放的最高档位 |
| 视频最高仅为 720p | 播放 720p，不重复请求高档位 |
| 高档位编码不支持，但有兼容的 1080p | 能力筛选后选择兼容的最高档位 |
| 已选最高画质加载失败，恢复预算耗尽 | 回退 720p，保持进度和播放状态 |
| 视频也不提供 720p | 使用可用更低画质并显示真实档位 |
| 登录失效 | 提示重新登录，按服务器实际能力回退 |
| 用户手动选择 720p | 本片不被自动升回最高；可手动恢复自动模式 |
| 自动模式下播放过程中登录成功 | 只切源一次，保持当前进度和暂停状态 |
| 电脑房主和手机观众账号权限不同 | 各自使用本机画质，播放进度继续同步 |
| 切换影片、分 P 或账号 | 按新的视频和账号重新选择，不复用失效缓存 |
| API 返回 qn 与最终轨道 ID 不一致 | 菜单显示最终轨道画质，不显示请求值 |

解析策略、权限回退和真实画质判断需要有针对性的自动化验证；编码能力、音画同步、seek 和前后台恢复必须使用真实 Android WebView 测试。
